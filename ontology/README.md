# The POKE ontology

`repo/` is a RouteMind data repository generated by `tools/ontology.py` from what this repository
already knows: every `device.json` in `edge/library`, the design documents, the skills, and the
AI-incubation results. Four areas, each advertising itself in one `use_when` line — PLATFORM,
DRIVERS, DEVICES, SKILLS — read by an agent the RouteMind way: the list of areas, one area, one node.

It is committed so the map can be reviewed like code, and regenerated rather than edited:
`regions.json` is derived. An identification is advertised as a recipe only when a driver written
from it passed verification; anything else is an open question that says so — a map an agent trusts
passes its errors on silently.

Serving it needs RouteMind's `knowledge-ontology` image and the directory to be its own git
repository, so the container mounts a mirror at `run/repo` (ignored): run `tools/ontology.py`, then
`git -C ontology/run/repo add -A && git -C ontology/run/repo commit -m …`, then
`docker restart poke-ontology`. `sim/body/incubate2.py` does this on every registration.

```sh
docker run -d --name poke-ontology --user $(id -u):$(id -g) -p 8120:8100 \
  -e ONTOLOGY_DATA=/data/repo -e ONTOLOGY_PUBLISH=/data/publish -e ONTOLOGY_OVERLAYS=/data/overlays \
  -e ONTOLOGY_WALKS=/data/walks -e ONTOLOGY_HARNESS=/data/harness -e ONTOLOGY_ACCESS=/data/access \
  -v $PWD/ontology/run/repo:/data/repo -v $PWD/ontology/run/publish:/data/publish \
  -v $PWD/ontology/run/overlays:/data/overlays -v $PWD/ontology/run/walks:/data/walks \
  -v $PWD/ontology/run/harness:/data/harness -v $PWD/ontology/run/access:/data/access \
  knowledge-ontology:0.1.0
```

Agents reach it through `sim/body/routemind.py` (`knowledge_table`, `knowledge_read`;
`POKE_KNOWLEDGE_API` defaults to http://localhost:8120).
