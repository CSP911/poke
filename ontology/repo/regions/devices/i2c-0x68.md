# I2C 0x68 — DS1307/DS1338-compatible I2C real-time clock
**Status: verified.** The resident `i2c-rtc-68` was written from this identification and its readings
matched ground truth on the twin (2026-10-06 00:26).

**Evidence:** Registers 0x00-0x06 decode as valid BCD time/date: 0x42,0x54,0x15,0x03,0x06,0x10,0x26 -> 15:54:42 on 2026-10-06 (24h mode, CH/clock-halt bit clear so it's running). A follow-up lone read of reg 0x00 a few calls later returned 0x48 (48s), i.e. seconds advanced from 42->48, proving the clock is live-ticking in real time rather than a static canned value (consistent with the QEMU ds1338 model following the host clock in UTC). Also checked the MPU6050 alternative hypothesis for this address: MPU6050's WHO_AM_I at register 0x75 should read 0x68, but it read 0x00, ruling that out. Control reg 0x07 not re-checked this session but previously read 0x00 (square wave disabled).

**Reading:** Read 7 bytes from reg 0x00: [sec,min,hour,dow,date,month,year] all BCD; sec bit7=CH(clock halt, currently 0=running); hour bit6=0 selects 24h mode. Compose as hh:mm:ss on 20YY-MM-DD.
