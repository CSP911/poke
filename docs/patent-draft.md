# 특허 명세서 초안

## 발명의 명칭

인공지능 기반 기계어 코드 실시간 생성 및 베어메탈 하드웨어 주입 실행 시스템 및 방법

**System and Method for Real-Time Machine Code Generation and Bare-Metal Hardware Injection Execution Using Artificial Intelligence**

---

## 기술분야

본 발명은 대규모 언어 모델(LLM)을 이용하여 자연어 명령으로부터 기계어 코드를 실시간으로 생성하고, 운영체제 없이 동작하는 베어메탈 하드웨어 장치에 상기 코드를 주입하여 실행하는 시스템 및 방법에 관한 것이다.

---

## 배경기술

종래의 하드웨어 제어 기술은 운영체제(OS), 디바이스 드라이버, 라이브러리, 애플리케이션 등 다층 소프트웨어 스택을 필요로 한다. 하드웨어를 제어하기 위해서는 해당 하드웨어에 대응하는 드라이버를 사전에 컴파일하여 설치하여야 하며, 새로운 하드웨어가 추가될 때마다 드라이버 개발 및 통합 과정이 필요하다.

최근 대규모 언어 모델(LLM)의 발전으로 자연어로부터 프로그래밍 코드를 생성하는 기술이 발전하였으나, 이러한 기술은 고수준 프로그래밍 언어(Python, JavaScript 등)의 생성에 한정되어 있으며, 생성된 코드의 실행을 위해서는 여전히 운영체제, 인터프리터 또는 런타임 환경이 필요하다.

또한, IoT(사물인터넷) 분야에서 디바이스 프로파일을 통한 장치 관리 기술이 제안되어 있으나(US10855800, US11748518), 이들은 API 수준의 추상화에 그치며 레지스터 수준의 직접 하드웨어 제어를 제공하지 못한다.

따라서, 운영체제 및 드라이버 없이 자연어 명령만으로 임의의 하드웨어를 직접 제어할 수 있는 기술이 요구된다.

---

## 발명이 해결하고자 하는 과제

본 발명은 다음의 기술적 과제를 해결하고자 한다:

1. 운영체제, 드라이버, 사전 컴파일된 소프트웨어 없이 자연어 명령으로 하드웨어를 직접 제어하는 방법의 제공
2. 대규모 언어 모델이 하드웨어 레지스터 수준의 기계어 코드를 실시간으로 생성하는 방법의 제공
3. 생성된 바이너리 코드가 일회성으로 실행 후 폐기되는 휘발성 바이너리 실행 패러다임의 제공
4. 하드웨어 디바이스 프로파일로부터 AI 에이전트 도구를 자동으로 생성하는 방법의 제공

---

## 과제의 해결수단

### 제1 양태: 기계어 코드 실시간 생성 및 주입 시스템

본 발명의 제1 양태에 따른 시스템은:
- 자연어 명령을 수신하여 처리하는 허브(Hub) 장치; 및
- 네트워크를 통해 상기 허브와 연결되고, 운영체제 없이 동작하며, 수신된 기계어 코드를 직접 실행하는 적어도 하나의 엣지(Edge) 장치를 포함하며,

상기 허브 장치는:
a) 자연어 명령을 수신하는 수신부;
b) 대규모 언어 모델(LLM)을 이용하여 상기 자연어 명령을 해석하고, 대상 엣지 장치의 아키텍처(x86, ARM64 등)에 적합한 기계어 코드를 생성하는 코드 생성부;
c) 상기 생성된 기계어 코드를 어셈블링하여 실행 가능한 바이너리로 변환하는 내장 어셈블러;
d) 상기 바이너리를 실행 전에 위험 명령어(HLT, CLI 등) 및 위험 메모리 접근을 검사하는 보안 스캐너; 및
e) 검증된 바이너리를 네트워크(HTTP 또는 시리얼 프로토콜)를 통해 엣지 장치에 전송하는 전송부를 포함하고,

상기 엣지 장치는:
a) 프로세서를 보호 모드(Protected Mode)로 초기화하고 네트워크 스택(TCP/IP)을 구현하는 최소 커널;
b) HTTP를 통해 바이너리 코드를 수신하는 수신부;
c) 수신된 코드를 실행 버퍼에 복사하여 프로세서가 직접 실행하는 실행부; 및
d) 실행 결과를 허브에 반환하는 응답부를 포함한다.

### 제2 양태: 휘발성 바이너리 실행 방법

본 발명의 제2 양태에 따른 방법은:
a) 사용자로부터 자연어 명령을 수신하는 단계;
b) 대규모 언어 모델이 상기 명령을 해석하여 대상 하드웨어에 적합한 기계어 코드를 생성하는 단계;
c) 내장 어셈블러가 상기 기계어 코드를 바이너리로 변환하는 단계;
d) 보안 스캐너가 상기 바이너리에서 위험 명령어를 검사하는 단계;
e) 상기 바이너리를 엣지 장치에 네트워크를 통해 전송하는 단계;
f) 상기 엣지 장치가 운영체제 없이 상기 바이너리를 프로세서에서 직접 실행하는 단계;
g) 실행 결과를 허브에 반환하는 단계; 및
h) 상기 바이너리를 폐기하는 단계를 포함하며,

상기 바이너리는 사전에 컴파일되어 저장되지 않고, 요청 시 실시간으로 생성되어 1회 실행 후 폐기되는 것을 특징으로 한다.

### 제3 양태: 디바이스 프로파일 기반 AI 에이전트 도구 자동 생성 방법

본 발명의 제3 양태에 따른 방법은:
a) 하드웨어 장치의 레지스터 맵, 주소, 기능을 기술한 디바이스 프로파일(JSON 형식)을 로딩하는 단계;
b) 상기 프로파일에 정의된 각 오퍼레이션(operation)에 대해, 대규모 언어 모델의 도구 호출(tool_use) 인터페이스에 적합한 에이전트 도구를 자동으로 생성하는 단계;
c) 상기 에이전트 도구가 호출될 때, 프로파일에 기록된 어셈블리 코드를 어셈블링하여 대상 엣지 장치에 전송하고 실행하는 단계를 포함하며,

새로운 하드웨어 장치가 연결될 때, 상기 장치의 PCI 버스를 스캔하여 디바이스 정보를 수집하고, 대규모 언어 모델이 프로브 코드를 생성하여 장치 특성을 탐지하며, 상기 탐지 결과를 기반으로 디바이스 프로파일을 자동으로 생성하는 것을 특징으로 한다.

---

## 발명의 효과

1. **운영체제 불필요**: 드라이버, 라이브러리, 애플리케이션 설치 없이 자연어만으로 하드웨어를 제어할 수 있다.
2. **소프트웨어 업데이트 불필요**: 바이너리가 매 실행 시 새로 생성되므로 버전 관리, 패치, 업데이트가 필요 없다.
3. **보안 강화**: 휘발성 바이너리는 실행 후 폐기되므로 악성코드가 지속적으로 상주할 수 없다.
4. **하드웨어 독립성**: 디바이스 프로파일만 있으면 제조사에 관계없이 모든 하드웨어를 동일한 방식으로 제어할 수 있다.
5. **자동 확장**: 새로운 하드웨어 연결 시 프로파일이 자동 생성되어 즉시 제어 가능한 도구가 제공된다.

## 발명을 실시하기 위한 구체적인 내용

### 시스템 구성도

```
[사용자] --자연어--> [허브(Hub)]
                        |
                   [LLM 에이전트 루프]
                   observe → think → act → check
                        |
                   [내장 어셈블러 (asm.js)]
                   어셈블리 텍스트 → 바이너리 바이트
                        |
                   [보안 스캐너]
                   위험 명령어/포트/메모리 검사
                        |
            +-----------+-----------+
            |           |           |
       [엣지 #1]   [엣지 #2]   [엣지 #3]
       x86 베어메탈  ARM64      모바일
       HTTP /poke   UART       브라우저
```

### 허브(Hub) 상세 구현

허브는 Node.js 기반 서버로 구현되며, 다음의 주요 모듈을 포함한다:

1. **에이전트 루프 (Agent Loop)**: Claude Code, Codex 등 기존 코딩 에이전트와 동일한 observe-think-act-check 루프를 사용하되, 도구(tool)가 소프트웨어가 아닌 하드웨어 장치이고, 파라미터가 어셈블리 코드인 점에서 차별화된다.

2. **내장 어셈블러 (asm.js)**: x86-32 및 ARM64 아키텍처의 어셈블리 니모닉을 바이너리 바이트로 변환하는 순수 JavaScript 구현체로, nasm, gcc 등 외부 컴파일러에 대한 의존성이 없다.

3. **보안 스캐너**: 생성된 바이너리를 3단계로 검사한다.
   - 제1층 (asm.js): 어셈블링 시 위험 명령어(HLT, CLI, STI, WBINVD), 위험 I/O 포트(시스템 리셋, 키보드 컨트롤러), 보호 메모리 영역 접근을 검사
   - 제2층 (허브 컴파일러): 전송 전 최종 바이너리 검증
   - 제3층 (엣지 커널): 베어메탈에서 실행 직전 코드 버퍼를 재검사

4. **디바이스 프로파일 엔진**: JSON 형식의 프로파일을 로딩하여, 각 오퍼레이션을 LLM tool_use 인터페이스의 도구로 자동 변환한다.

### 엣지(Edge) 상세 구현

엣지 장치는 24KB 미만의 최소 커널로 구현되며:
- 부트로더: x86 Real Mode → Protected Mode 전환, A20 라인 활성화, GDT 설정
- 네트워크: e1000 NIC 드라이버(PCI MMIO), ARP, IP, TCP 3-way handshake, HTTP 서버
- 코드 실행: 수신된 바이너리를 실행 버퍼에 복사하고 함수 포인터로 호출, 결과(EAX 레지스터 값 또는 텍스트)를 HTTP 응답으로 반환

### 휘발성 바이너리 생명주기

```
t=0ms    사용자 명령 수신 ("calculate 100 * 7")
t=50ms   LLM이 어셈블리 생성 ("mov eax, 100; imul eax, 7; ret")
t=51ms   내장 어셈블러가 바이너리 변환 (9 bytes: B8 64 00 00 00 6B C0 07 C3)
t=52ms   보안 스캐너 검증 통과
t=55ms   엣지에 HTTP POST 전송
t=60ms   엣지 CPU가 베어메탈에서 실행, EAX=700
t=65ms   결과 반환
t=66ms   바이너리 폐기 (엣지 실행 버퍼 다음 요청 시 덮어씀)

총 생명주기: ~66ms. 바이너리는 어디에도 저장되지 않는다.
```

### 디바이스 프로파일 예시

```json
{
  "vendor_device": "8086:100E",
  "name": "Intel 82540EM (e1000)",
  "type": "network",
  "arch": "i386",
  "bar0": { "address": "0xfebc0000" },
  "operations": [
    {
      "name": "read_mac",
      "desc": "Read MAC address from e1000 NIC",
      "asm": "BITS 32\nmov ebx, 0xfebc0000\nmov eax, [ebx + 0x5400]\nret",
      "returns": "MAC low 32 bits in EAX"
    }
  ]
}
```

상기 프로파일이 로딩되면, `network_read_mac()` 도구가 자동 생성되어 LLM 에이전트가 직접 호출할 수 있다.

### 자동 프로파일 생성 과정

1. 엣지 장치의 PCI 버스를 스캔하는 기계어 코드를 생성하여 주입
2. 각 PCI 슬롯의 Vendor ID, Device ID, BAR0 주소를 수집
3. 수집된 정보를 LLM에 전달하여 디바이스 식별 및 프로브 코드 생성
4. 프로브 코드 실행 결과를 분석하여 디바이스 프로파일 JSON 자동 생성
5. 생성된 프로파일 저장 및 에이전트 도구 즉시 갱신

## 청구범위

### 독립항

**제1항** 자연어 명령을 수신하여 대규모 언어 모델(LLM)이 대상 하드웨어 아키텍처에 적합한 기계어 코드를 실시간으로 생성하고, 내장 어셈블러를 통해 바이너리로 변환하며, 보안 검증을 거친 후, 운영체제 없이 동작하는 베어메탈 엣지 장치에 네트워크를 통해 전송하여 직접 실행하고, 실행 후 상기 바이너리를 폐기하는 것을 특징으로 하는 인공지능 기반 하드웨어 제어 방법.

**제2항** 하드웨어 장치의 레지스터 주소, 오프셋, 접근 방법을 기술한 디바이스 프로파일을 로딩하고, 상기 프로파일의 각 오퍼레이션에 대해 대규모 언어 모델의 도구 호출(tool_use) 인터페이스에 적합한 에이전트 도구를 자동으로 생성하며, 상기 도구가 호출될 때 프로파일에 기록된 어셈블리 코드를 어셈블링하여 대상 엣지 장치에서 실행하는 것을 특징으로 하는 디바이스 프로파일 기반 AI 에이전트 도구 자동 생성 방법.

**제3항** 제1항의 방법을 실행하기 위한 시스템으로서, 대규모 언어 모델 에이전트 루프, 내장 어셈블러, 다층 보안 스캐너를 포함하는 허브 장치와; 운영체제 없이 최소 커널만으로 동작하며 수신된 기계어 코드를 프로세서에서 직접 실행하는 적어도 하나의 엣지 장치를 포함하는 것을 특징으로 하는 인공지능 기반 베어메탈 하드웨어 제어 시스템.

### 종속항

**제4항** 제1항에 있어서, 상기 바이너리는 사전에 컴파일되어 저장되지 않고, 각 명령 요청 시마다 실시간으로 생성되어 1회 실행 후 폐기되는 것을 특징으로 하는 방법.

**제5항** 제1항에 있어서, 상기 보안 검증은 위험 명령어(HLT, CLI, STI, WBINVD) 검출, 위험 I/O 포트 접근 검출, 보호 메모리 영역 쓰기 검출을 포함하는 3단계 검사를 수행하는 것을 특징으로 하는 방법.

**제6항** 제1항에 있어서, 상기 내장 어셈블러는 외부 컴파일러(nasm, gcc 등)에 대한 의존성 없이 순수 JavaScript로 구현되어, x86-32 및 ARM64 아키텍처의 어셈블리 니모닉을 바이너리 바이트로 변환하는 것을 특징으로 하는 방법.

**제7항** 제2항에 있어서, 새로운 하드웨어 장치가 연결될 때, PCI 버스를 스캔하는 기계어 코드를 자동 생성하여 엣지 장치에서 실행하고, 수집된 디바이스 정보를 기반으로 대규모 언어 모델이 프로브 코드 생성 및 디바이스 프로파일 자동 생성을 수행하는 것을 특징으로 하는 방법.

**제8항** 제3항에 있어서, 상기 허브 장치는 복수의 엣지 장치에 대해 태스크를 의미적으로 분해하여 병렬로 배분하고, 각 엣지의 실행 결과를 수집하여 합산하는 분산 컴퓨팅 기능을 포함하는 것을 특징으로 하는 시스템.

**제9항** 제3항에 있어서, 상기 에이전트 루프는 관찰(observe)-사고(think)-행동(act)-확인(check) 단계를 반복하며, 상기 행동 단계에서 하드웨어 장치를 도구(tool)로, 어셈블리 코드를 파라미터로 사용하는 것을 특징으로 하는 시스템.

**제10항** 제1항에 있어서, 상기 엣지 장치는 외부 데이터(기상 API 등)와 로컬 하드웨어 데이터(센서 레지스터 등)를 하나의 바이너리에 결합하여 실행하며, 상기 외부 데이터는 허브에서 수집되어 바이너리의 즉시값(immediate value)으로 주입되는 것을 특징으로 하는 방법.

## 요약

본 발명은 대규모 언어 모델(LLM)을 이용하여 자연어 명령으로부터 기계어 코드를 실시간으로 생성하고, 운영체제 없이 동작하는 베어메탈 하드웨어에 네트워크를 통해 주입하여 실행하는 시스템 및 방법에 관한 것이다. 생성된 바이너리는 1회 실행 후 폐기되는 휘발성 바이너리로서, 소프트웨어 업데이트, 버전 관리, 악성코드 상주 문제를 근본적으로 해결한다. 또한, 하드웨어 디바이스 프로파일로부터 AI 에이전트 도구를 자동으로 생성하여, 새로운 하드웨어 연결 시 즉시 제어 가능한 인터페이스를 제공한다.
