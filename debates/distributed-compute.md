# 연산 분산 — 설계

## 개요

```
허브: "1부터 1억까지 합 구해"
  → 작업 분할 (LLM 또는 허브 로직)
  → 엣지 A: 1~2500만
  → 엣지 B: 2500만~5000만
  → 엣지 C: 5000만~7500만
  → 엣지 D: 7500만~1억
  → 결과 수집 → 합산 → 응답
```

## 프로토콜

### 1단계: 작업 제출
```
POST /compute
{
  "task": "sum from 1 to 100000000",
  "strategy": "split"    // split | replicate | pipeline
}
```

### 2단계: 허브가 분할
```
허브 판단:
  - 등록된 엣지: 4대
  - 각 엣지 상태: alive, cpu_busy=false
  - 분할: 4등분

생성할 코드 4개:
  엣지 A: sum(1, 25000000)
  엣지 B: sum(25000001, 50000000)
  엣지 C: sum(50000001, 75000000)
  엣지 D: sum(75000001, 100000000)
```

### 3단계: 병렬 실행
```
허브 → 엣지 A: POST /poke (코드 A)  ─┐
허브 → 엣지 B: POST /poke (코드 B)   │ 동시 전송
허브 → 엣지 C: POST /poke (코드 C)   │
허브 → 엣지 D: POST /poke (코드 D)  ─┘

각 엣지: 실행 → eax 반환
```

### 4단계: 결과 수집 + 합산
```
엣지 A → eax=312500012500000
엣지 B → eax=937500012500000
엣지 C → eax=1562500012500000
엣지 D → eax=2187500012500000
합산 → 5000000050000000
```

## 분산 전략 3가지

### Split (분할)
```
하나의 작업을 N등분.
각 엣지가 일부를 처리.
결과를 합산.

적합: 합계, 검색, 필터링, 맵리듀스
```

### Replicate (복제)
```
같은 작업을 여러 엣지에서 실행.
가장 빠른 결과를 채택.
또는 다수결로 검증.

적합: 신뢰성 필요, 결과 검증, 레이턴시 최소화
```

### Pipeline (파이프라인)
```
A의 결과를 B의 입력으로.
B의 결과를 C의 입력으로.
순차 처리.

적합: 이미지 처리 (변환 → 필터 → 압축), 데이터 가공
```

## 허브 API 설계

```
POST /compute
{
  "task": "자연어 또는 코드",
  "strategy": "split",          // split | replicate | pipeline
  "reduce": "sum",              // sum | min | max | concat | first | vote
  "target_nodes": [],           // 비어있으면 자동 선택
  "timeout_ms": 10000
}

Response:
{
  "task": "...",
  "strategy": "split",
  "edges_used": ["qemu-01", "qemu-02", "qemu-03"],
  "results": [
    { "node": "qemu-01", "eax": 312500012500000, "time_ms": 230 },
    { "node": "qemu-02", "eax": 937500012500000, "time_ms": 245 },
    { "node": "qemu-03", "eax": 1562500012500000, "time_ms": 220 }
  ],
  "reduced": 5000000050000000,
  "total_time_ms": 250
}
```

## 구현 순서

```
1. QEMU 엣지 여러 대 띄우기 (포트 다르게)
2. 허브에 /compute 엔드포인트 추가
3. LLM이 작업 분할 코드 생성
4. 병렬 전송 + 결과 수집
5. reduce 처리
6. 데모: 단일 엣지 vs 분산 속도 비교
```

## 32비트 한계

```
현재 POKE OS는 i386 (32비트)
→ EAX는 최대 2^32 = 4,294,967,296
→ 1~1억 합 = 5,000,000,050,000,000 → 32비트 초과!

해결:
  A. 64비트 반환 (EAX + EDX 조합)
  B. result_buf에 문자열로 반환
  C. 작업을 더 작게 분할 (32비트 안에 들어오도록)
  D. POKE OS를 64비트로 업그레이드 (장기)
```

## 데모 시나리오

```
[데모 1: 소수 찾기]
"1~100000 사이 소수의 개수"
→ 4등분 → 각 엣지가 자기 범위에서 소수 카운트 → 합산
→ 단일: 3초 vs 4대 분산: 0.8초

[데모 2: 해시 충돌 찾기]
"이 해시의 원문 찾기" (브루트포스)
→ 탐색 범위를 N등분 → 찾으면 즉시 반환

[데모 3: 이미지 처리 파이프라인]
"이 이미지를 밝게 → 흐리게 → 축소"
→ 엣지 A: 밝기 조절 → 엣지 B: 블러 → 엣지 C: 축소
→ 파이프라인 방식
```
