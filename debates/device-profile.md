# 기기 프로파일 — POKE의 핵심 자산

## 개요

```
POKE가 기기를 제어하려면 → 그 기기를 "알아야" 함
알아야 하는 것: 칩, 레지스터, 주변장치, 통신 방식
이 정보 = "기기 프로파일"
프로파일이 많을수록 = POKE가 더 많은 기기를 제어
```

## 프로파일 구조

```json
{

  "arch": "arm-cortex-m4",

```

## 프로파일 수집 3단계

### 1단계: 자동 탐색 (enroll 시)
```
기기가 POKE 네트워크에 등록될 때:
  → 탐색 코드 주입: 칩 ID 읽기, 메모리 맵 스캔
  → 결과: "이 기기는 STM32F401, GPIO 48개, I2C 3개"
  → 자동으로 기본 프로파일 생성
```

### 2단계: 커뮤니티 축적
```
사용자가 기기를 성공적으로 제어하면:
  → 그 조합(기기 + 명령 + 코드)이 프로파일 DB에 추가
  → 다른 사용자가 같은 기기를 쓸 때 바로 활용

예:
  사용자 A: "삼성 에어컨 AR12 → 25도" 성공
  → 프로파일: { device: "삼성 AR12", command: "set_temp", code: "..." }
  사용자 B: 같은 에어컨 → 이미 프로파일 있음 → 바로 동작
```

### 3단계: 제조사 제공
```
제조사가 직접 POKE 프로파일을 공개
  → "우리 기기의 레지스터 맵은 이거예요"
  → POKE 생태계 참여 = 사용자 접근성 증가
  → 제조사에게도 이득 (앱 개발 안 해도 됨)
```

## 선순환

```
프로파일 축적 → 더 많은 기기 제어
→ 더 많은 사용자 → 더 많은 기기 연결
→ 더 많은 프로파일 → ...

이것이 POKE의 네트워크 효과.
앱스토어의 "앱 수"가 경쟁력이듯,
POKE의 "프로파일 수"가 경쟁력.
```

## 구현 계획

```
1단계: 프로파일 JSON 스키마 정의
2단계: 자동 탐색 코드 (칩 ID 읽기)
3단계: 허브에 프로파일 DB
4단계: LLM이 프로파일 참조해서 코드 생성
5단계: 성공한 명령 자동 프로파일 등록
```
