# 문장 부팅 안전 결론 — 2026-10-11 밤 ~ 10-12 아침 (검사기팀)

## 한 쪽 요약 (아침 보고 인용용)

**결론: 모델이 쓴 코드는 노드를 망가뜨릴 수 없고, 허락받지 않은 행동도 할 수 없다 — 트윈에서 구조적으로 확인됨. 실기기 확인은 남았다.**

- **경계가 바뀌었다.** 어제 op는 EL2 전권으로 돌았고 정적 검사가 유일한 벽이었다. 지금 op는 **EL0**에서 자기 페이지만 보는 페이지 테이블 안에서 돈다. 하드웨어 창은 **0개** — UART·전원·GPIO·I2C 컨트롤러 모두 런타임(EL1) 전용이고, op는 런타임 호출(svc 9개)로만 바깥에 닿는다. 정적 검사는 모델에게 빠른 피드백을 주는 린트로 내려왔다.
- **버스 행동은 허용 목록이 정한다.** I2C 전송마다 런타임이 이미지에 박힌 허용 목록(장치·레지스터·길이·**값 범위·쓰기 횟수**)과 대조하고, 밖이면 이유를 보고하며 노드를 끈다. 목록은 허브가 op의 MANIFEST와 허브 정책 표에서 만든다 — 모델의 말이 아니다.
- **노드가 실제로 한 일이 증거로 남는다.** 런타임이 모든 전송을 기록해 `POKE-EFFECTS2`로 보고(op 위조 불가)하고, 허브가 manifest와 대조한다. 이 기록이 결함 재시도(방을 바꾼 뒤엔 사람에게 묻기), 상시 감시 판정, 인큐베이팅 최소 권한의 근거다.
- **아무것도 남지 않는다.** 리셋 직전 op 페이지·결과·페이지 테이블·런타임 스택을 0으로 지우고, 허브가 리셋 뒤 메모리를 직접 읽어 확인한다(약 76–80 KB, 0이 아닌 바이트 0).
- **무인 동작에는 상한이 있다.** 상시 감시는 읽기 전용 op만, 60초 이상 간격, 하루 1,440회, 동시 4개, 24시간 만료, 연속 2회 실패 시 중지, 조건이 맞아도 행동은 사람이 확인. 감사 19항목 중 17 강제 확인, 2건은 제품 수정 중.
- **스스로 배운 장치는 심사를 거친다.** 인큐베이팅 결과는 검증 실행에서 실제로 관측된 쓰기만 권한으로 남기고, 식별 신뢰도 0.8 미만이면 쓰기 함수 거부(SSD0303 화면 쓰기 deny 적용).
- **작다.** 런타임 9.7 KB(3페이지), 이미지 16.4 KB, 상주 0, 초기화 데이터 0. not-linux 7규칙 중 예외 1건(I2C 컨트롤러를 런타임이 쥠 — 허용 목록 강제를 위해 의식적으로).
- **실기기에서만 확인될 것:** GIC 타이머 인터럽트·PM 워치독, 캐시 끈 MMU의 실제 성능, I2C 클록(CDIV 5000), 실제 핀 설정, 차가운 칩(DPS310 설정 쓰기), UART 마지막 줄.

시험(모델 호출 0, 매번): boottest 22 · checktest 12 · t_v6 11 · t_v7 6 · t_watch 19 · t_learn 15 · t_x2/x3/r2/r3 17 · pt_test 30 — regress --quick 151건에 편입.

## 3. 남은 위험 (트윈에서 알고 있는 것)

1. **값 범위는 장치 지식에 달렸다.** 범위·횟수 칸은 FN 표에 사람이(또는 심사를 거친 학습이) 넣어야 효과가 있다. 지금 LED는 범위가 의미 없어 비어 있다. 서보·히터가 들어오기 전 반드시 채울 것.
2. **포인터 비트로 자동 증가를 켜는 부품**(PCA9552류)은 auto_increment 의미로 표현되지 않는다 → 범위를 넓게 둬야 한다(ai_mask 칸 미구현).
3. **최소 권한은 검증 시험이 통과한 경로만큼이다.** 의장 결정으로 DPS310에도 심사를 적용했다(08:3x): 설정 쓰기 0x06–0x08 권한 **제거**(write_regs []), 심사 안 된 쓰기 권한은 이제 0. 트윈 칩은 이미 설정된 상태라 '기압 알려줘'는 그대로 동작(t_newparts 5/5). **실칩에서는 전원 직후 설정이 필요해 첫 읽기가 kind=i2c로 거절된다(안전한 실패)** — 차가운 상태 시험을 실칩에서 통과시킨 뒤 설정 쓰기를 재심사해야 한다(incubated/dps310.json `real_chip_todo`). 심사는 이제 **통과한 검증 실행만** 근거로 쓴다(실패한 차가운 상태 실행의 쓰기는 권한이 되지 않음).
4. **상시 감시 구멍 2건**(제품 수정 중): 근원 기록이 지워져도 감시 계속; 감시가 부른 행동에 '항상'이라 답하면 승인이 저장됨.
8. **학습 고리**: 5차 2부의 구멍 4건(식별 탐침의 쓰기, 동시 학습, 반쯤 등록, 검증 이미지 재작성)은 실기기 5차에서 고쳐짐 — t_learn 15/15. `reconcile_orphans`는 fn.json을 쓰지만 회수만 함(추가·확장 0을 시험으로 고정).
5. **런타임은 한 번 감사하는 고정 코드다.** svc 처리기는 IRQ를 막고 돈다 — 모든 경로가 유한함을 감사했지만, 새 svc마다 같은 감사가 필요.
6. **물리적 결과는 메모리 격리로 못 막는다.** LED를 켜 둔 채 끝나는 것 같은 '허락된 행동의 결과'는 정책·확인의 영역.
7. 캐시되지 않은 같은 문장의 동시 생성은 키 잠금으로 모델 1회(제품 D2) — 다른 프로세스가 잠금 없이 build를 부르는 경로가 새로 생기면 재확인.

## 다음 과제 (이번 밤에는 하지 않음)

- **신원 근거의 등급**(실기기 제안): identify가 판정 근거를 'ID 레지스터 / 레지스터 배치 / 행동'으로 나눠 보고하고, V7 심사는 **ID 레지스터로 확인된 신원만** 쓰기 권한의 근거로 인정한다(배치·행동만으로 식별된 부품은 쓰기 deny 또는 사람 확인). SSD0303처럼 읽을 ID가 없는 부품의 처리 규칙도 함께.
- 값 범위의 `ai_mask` 칸(포인터 비트로 자동 증가를 켜는 부품).
- DPS310 실칩 차가운 상태 시험 후 설정 쓰기 재심사.

| 리셋 뒤 0 채우기 | 실측은 트윈 QMP로만 | 실기기는 다음 부팅의 이미지가 덮어씀 — 직접 측정 수단 없음(남은 위험) |

### 지켜볼 것

- **효과 기록(X1)이 가장 큰 최근 증가(+1.9 KB 코드, +1.4 KB RAM)**. 상세 32건 표를 16건으로 줄이거나 JSON 서식을 허브 쪽으로 넘기면(이진 기록 + 허브 해석) 약 1 KB를 줄일 수 있음. 이미지는 다시 3페이지가 됨.
- svc 처리기는 IRQ를 막은 채 돎. 모든 경로가 유한함을 감사함(문자열 ≤ 199, I2C ≤ 64바이트·폴링 20000회, delay는 예산까지). 새 svc를 넣을 때 같은 감사가 필요.
- 런타임 RAM의 대부분은 페이지 테이블(6×4 KB). 2 MB 블록으로 줄이면 op·런타임 분리가 4 KB 단위로 안 되므로 유지.
