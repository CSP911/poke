# 제품팀 2라운드 결정안 (2026-10-11)

## 1. "전원 종료" 문구
- 기본 상태 이름: **"비움 · 부트로더 대기"** (우리 코드 실행 0, 제조사 부트로더만 동작). "전원 종료"는 halt 모드에만 쓴다.
- 리셋 전에 런타임이 op 영역과 스택을 0으로 지운다(DRAM 잔존 바이트 축소). 지운 바이트 수를 POKE-END에 보고한다.
- halt(PMIC 차단)는 v0 기본값에서 뺀다. GLOBAL_EN 웨이크 선이 생긴 뒤 `--halt` "완전 소등" 모드로 넣는다. 용도는 빈 몸 증명(더늠 심판)과 저전력.

## 2. 의도 선언(manifest) 초안
```
{"reads": ["tmp105"], "writes": [{"dev": "led", "what": [0], "end": "leave"}], "max_s": 2}
```
- 작성: 모델이 op를 쓰기 전에 문장에서 manifest를 먼저 쓴다(op와 별도 출력).
- 상한: 허브의 장치 정책 표(소유자가 정함). 기본값은 read 허용, LED 쓰기 허용, rtc_set 금지, 향후 구동기는 항상 확인.
- 강제: 검사기가 op에 링크된 조각 함수가 manifest의 부분집합인지 확인한다(조각을 read/write 헤더로 분리하는 것이 전제).
- 확인: 읽기만 하는 문장은 즉시 실행한다. 쓰기가 있으면 한국어 한 줄("LED 0을 켭니다. 나머지는 그대로")을 보여 주고 승인받는다. 승인은 문장 기록에 저장해 캐시 재사용 시 다시 묻지 않는다. 금지 목록 장치는 승인과 무관하게 거부한다.

## 3. 시험팀 요청
- **시간대**: RTC는 UTC를 유지한다. 허브가 이미지에 `utc_offset_min`을 넣고, op는 현지 시각과 "KST" 라벨을 함께 보고한다.
- **모호한 문장**: 읽기가 모호하면 해당 센서를 전부 보고한다. 쓰기 대상이 모호하면 추측하지 않는다. 모델은 op 대신 `NEED: <질문>`을 내고, 허브는 부팅 없이 되묻는다. "불 좀 켜줘"는 되물음 대상이다.
- **20초 초과**: 부팅 전에 허브가 안내한다. 한 번에 20초가 넘는 일은 허브가 예약한 반복 부팅으로 나눈다. 기다림은 허브에 둔다. delay_ms 상한(D9)은 조용히 자르지 말고 fail로 바꾼다.

## 4. 다른 팀 제안
- 동의: EL0+MMU(이미지 16.5KB는 넷부팅 시간 대비 무시 가능), D1 부팅 시 워치독(실기기 필수), D4 결과 채널을 대역 밖으로(런타임만 결과 프레임을 쓰고 say는 이스케이프), D2 오류 처리.
- 반론: 외부 자료에 "20–30 ms"를 앞세우지 말 것. 실기기 숫자는 넷부팅 1.5–7초이고 실측 전이다.
- 수정된 Top 2: (1) 신뢰 게이트 = 부팅 직전 검사 강제(캐시 포함) + 부팅 워치독 + manifest·쓰기 확인. (2) 문장 기록 = 정규화·파라미터·결과 흔적·승인·시간대(더늠 카드 v0).
- 다음 세션 첫 작업: say.py의 부팅 경계에서 검사를 강제(캐시 경로 포함).
