# 아침 안내 — 문장 하나, 부팅 하나 (2026-10-11 밤 작업)

**무엇이 바뀌었나** — 노드가 op를 격리해서 돌리고(EL0), 끝나면 쓴 메모리를 0으로 지웁니다. 허브는 그 결과를 트윈 메모리에서 직접 읽어 확인합니다. 허브는 들은 문장을 **카드**로 기억합니다. 숫자만 다르거나 같은 뜻의 다른 말이면 모델을 부르지 않습니다. 장치를 바꾸는 문장은 먼저 묻고, 20초 넘는 요청은 여러 번 나눠 부팅합니다. "30도 넘으면 알려줘" 같은 문장은 허브가 지켜보며 읽기만 하는 부팅을 반복합니다(상한 있음). 부품을 옮긴 다른 몸에서도 문장을 다시 발음합니다. 화면과 출력은 모두 한국어입니다.
**5분 데모** — 화면 오른쪽 위 **데모 (5분)** 버튼을 누르면 8단계 이야기가 해설과 함께 자동으로 진행됩니다(약 50초~1분; 다른 몸 재발음에서 Claude Code 몇 초). 순서는 문장 → 같은 뜻 → 쓰기 확인 → 숫자만 바꿈 → 카드 → 다른 몸 재발음과 흔적 대조 → 지켜보기(보여만 줌)입니다. 데모는 기록 사본으로 돌고, 끝나면 소유자 기록과 몸이 원래대로 돌아옵니다. 데모 중에는 읽기·LED만 하고, '항상' 승인·배우기·지켜보기 시작은 꺼져 있습니다.
**먼저 해볼 것 세 가지** — ① `cd ~/poke/sentence && ../sim/body/.venv/bin/python ui/server.py`를 실행하고 http://127.0.0.1:8765 를 엽니다. ② 문장 버튼을 차례로 누릅니다: 온도 → LED 3번 → "불 좀 켜줘". ③ 오른쪽 목록에서 「온도 알려줘」를 눌러 카드를 봅니다. 끝낼 때는 터미널에서 Ctrl+C를 누릅니다. 지금 노드는 Pi가 아니라 QEMU 트윈입니다.

## 낱말 몇 개

| 말 | 뜻 |
|---|---|
| 노드 | 운영체제 없는 보드(지금은 QEMU 트윈). 문장마다 새 이미지로 부팅하고, 끝나면 리셋합니다 |
| op | 허브가 그 문장 하나만을 위해 쓰는 작은 C 프로그램(0.2–1.4 KB). 이미지 = 런타임 + 드라이버 조각 + op |
| manifest | op 맨 위에 붙은 선언: 어느 장치를 읽고 쓰는지, 사람에게 보일 한 줄 설명. 허브는 이걸로 확인 여부를 정하고, 노드는 선언하지 않은 장치 접근을 막습니다 |
| 이미지 검사 | 부팅 전에 op 기계어에 금지된 명령·주소가 없는지 봅니다. 거부되면 부팅하지 않습니다 |
| 비움 | 노드가 리셋 전에 이 부팅의 메모리를 0으로 지우는 것. 허브가 리셋 뒤 실제로 읽어 "0이 아닌 바이트 0"을 확인합니다 |
| 카드 | 허브가 기억하는 문장 하나: 들은 말들, 하는 일, 승인, 출처, 결과 흔적, 계보 |
| 몸 · 몸 지문 | 노드에 붙은 부품과 주소의 묶음. 지문은 그 묶음의 요약값으로, 기억된 op가 지금 몸에 맞는지 보는 데 씁니다 |
| 재발음 · 계보 | op가 지금 몸에 맞지 않을 때 같은 문장으로 op를 다시 쓰는 것이 재발음입니다. 이전 op는 카드의 계보에 남습니다 |

## 써볼 문장 (화면에 쓰거나, 터미널에서 `say.py "문장"`)

| 문장 | 볼 것 |
|---|---|
| 온도 알려줘 | 읽기라 묻지 않고 바로 실행. 기억된 문장이면 0.2–0.5초. 슬라이더를 27로 올리고 한 번 더 |
| 기온 어때? · 현재 시각은? · 온도 측정해줘 | 같은 뜻으로 알아보고 기존 카드를 씀. 처음엔 "“온도 알려줘”와 같은 뜻 — 규칙으로 판단, 모델 호출 0", 그다음부터는 카드에 들은 말로 남아 "기억에서" |
| LED 3번 켜줘 → LED 7번 켜 줘 | 먼저 확인 카드가 뜹니다. 7번은 처음 듣는 말이지만 3번 카드의 숫자만 바꿔 실행(모델 0). 3번도 켜진 채 남음(장치가 기억) |
| 온도가 25도 넘으면 LED 0번을 켜고, 아니면 꺼줘 | 슬라이더 23.75면 꺼짐, 27이면 켜짐. "30도"로 바꿔 말해도 모델 0 |
| 불 좀 켜줘 | 어느 LED인지 빠져 있어 부팅하지 않고 되물음 → "2번"이라고 답하면 확인 후 실행 |
| LED 20번 켜줘 · 사진 찍어줘 · 시계를 2020년 1월 1일 0시로 맞춰줘 | 범위 밖 / 카메라 없음 / 정책상 금지. 모두 부팅 0회, 이유를 바로 말함 |
| 온도가 30도 넘으면 알려줘 | **지켜보기**(상시 의도): 시작해도 되는지 묻고, 화면이 떠 있는 동안 60초마다 읽기만 하는 부팅으로 확인합니다. 슬라이더를 31로 올리면 다음 확인 때 알림(화면·맥 알림)이 오고 끝납니다. 오른쪽 "지켜보는 중"에서 멈출 수 있습니다. "지켜보다가 30도 넘으면 LED 0번 켜줘"는 조건이 맞을 때 LED를 켜지 않고 "확인하고 실행" 버튼만 띄웁니다 |
| 30초 동안 10초마다 온도 알려줘 | 허브가 10초마다 4번 부팅. 그 사이 노드는 꺼져 있고, 끝에 최저·평균·최고 |

처음 듣는 문장은 Claude Code가 op를 쓰느라 6–15초 걸리고, 다음부터는 기억에서 나옵니다.

## 터미널로 (화면과 같은 흐름)

```sh
cd ~/poke/sentence; P=../sim/body/.venv/bin/python
$P say.py "온도 알려줘"
$P say.py "LED 3번 켜줘"                          # 묻습니다: y 이번만 / a 항상(카드에 저장) / N
$P say.py "불 좀 켜줘" --answer "2번" --answer y   # 되물음과 확인에 미리 답함 (--yes는 확인만 건너뜀)
$P say.py memory                                  # 기억하는 문장 목록 · memory "온도 알려줘" = 카드
$P say.py watch                                   # 지켜보는 문장 · watch run(터미널에서 돌리기) · watch stop all
$P say.py --show --debug "온도 알려줘"              # op 소스, 원시 결과, 내부 오류까지
```

## 카드를 다른 몸으로 (더늠 시연, 약 1분)

TMP105 주소를 숫자로 박은 옛 op가 든 견본 카드를, 기록이 빈 두 번째 허브로 가져가서 TMP105를 0x4a로 옮긴 몸에서 실행합니다.

```sh
POKE_RECORDS=/tmp/hub2 $P say.py card import teams/product/cards/temp-old-0x48.json
POKE_RECORDS=/tmp/hub2 $P say.py --body teams/product/bodies/tmp105-0x4a.json "온도 알려줘"
#  [허브] 몸이 바뀜: 기본 실험대 → TMP105를 0x4a로 옮긴 몸 (온도 센서를 0x48에서 찾지만 이 몸에서는 0x4a에 있습니다)
#  [허브] 문장을 이 몸에 맞게 다시 발음 — Claude Code 약 6초
POKE_RECORDS=/tmp/hub2 $P say.py memory "온도 알려줘"   # 계보: 기본 실험대 → TMP105를 0x4a로 옮긴 몸
```

요즘 쓰는 op는 주소를 허브 상수로 받기 때문에, 내 카드(`say.py card export "온도 알려줘" 파일`)는 다른 몸에서도 다시 발음할 필요 없이 그대로 맞습니다. 화면으로 보려면 `POKE_RECORDS=/tmp/hub2 POKE_BODY=teams/product/bodies/tmp105-0x4a.json $P ui/server.py`로 띄웁니다. `POKE_BENCH=ext`로 띄우면 새 장치(원격 온도 TMP421, 확장 포트 PCA9554, OLED 화면)가 실험대에 나옵니다. 예: "원격 온도 센서 온도 알려줘". "화면에 HELLO 띄워줘"는 **안전 심사로 막힌 예**입니다. 밤사이 배운 OLED 화면은 허브가 부품을 확실히 알아보지 못해서(식별 신뢰도 0.70 < 0.8) 화면 쓰기가 금지된 채로 등록됐고, 그래서 그 문장은 허브 정책이 막습니다. 배운 부품이라도 확실하지 않으면 쓰지 못하게 하는 장면입니다.

## 배워줘 (처음 보는 부품)

`POKE_BENCH=ext`처럼 허브가 모르는 부품이 붙어 있으면 결과 아래에 "처음 보는 장치가 0x18에 있습니다" 카드와 **배워줘** 버튼이 뜹니다. 누르고 확인하면 백그라운드에서 버스 훑기 → 식별 → 조각 쓰기 → 트윈 검증 → 안전 심사 → 등록이 칸마다 켜지며 진행됩니다(몇 분, Claude Code 여러 번). 끝나면 기다리던 문장을 다시 실행하고, 실패하면 이유를 보여 준 뒤 그 주소를 '모름'으로 기억합니다. 터미널에서는 `$P say.py learn 0x18`입니다.

## 알아 둘 것

- 실기기(Pi 4)는 아직입니다. `say.py --preflight`로 준비 상태만 점검할 수 있습니다(지금은 USB-시리얼 어댑터와 10.0.0.1 주소, 두 가지가 없음).
- 트윈은 매 부팅 새로 시작합니다. LED가 켜진 채 남는 것은 데모 화면이 장치 상태를 다음 부팅에 넘겨 흉내 내는 것입니다. CLI는 매번 새 실험대입니다.
- 같은 뜻 규칙은 "한 장치를 그냥 읽는 문장"만 압니다. 그 밖은 짧은 모델 판정(4–5초)이나 새 op로 처리합니다.
- 기록은 `build/records/`에 있습니다(사용자 데이터, 커밋 안 함). 구조·명령·숫자·한계는 `sentence/README.md`에 있습니다.
